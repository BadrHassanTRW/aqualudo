# Task 09. Communications & Notifications

## Goal
Wire the two MVP communication channels: a WhatsApp deep-link button (static + booking-context aware) present site-wide, and a single transactional confirmation email sent via Resend when an admin confirms a booking. Footer contact details expose phone, WhatsApp, and email; a contact form posts leads to an API route that emails the owner. No queues, no retries, no template engine.

## Steps
1. **Centralize contact constants and WhatsApp link helper** — Create `lib/contacts.ts` exporting `WHATSAPP_NUMBER = "201011329642"`, `PHONE_DISPLAY = "+20 101 132 9642"`, `EMAIL_BOOKING`, `EMAIL_GENERAL`, and a `buildWhatsAppUrl(message: string)` helper returning `https://wa.me/${WHATSAPP_NUMBER}?text=${encodeURIComponent(message)}`. Files: `lib/contacts.ts`.
2. **Build a reusable WhatsAppButton component** — A floating circular button (bottom-right on mobile, bottom-right with offset on desktop) using the official WhatsApp green, with a tooltip "Chat on WhatsApp". Reads an optional `message` prop; falls back to a generic greeting. Files: `components/WhatsAppButton.tsx`. Notes: mounted in `app/layout.tsx` so it appears on every route; respects reduced-motion for any pulse animation.
3. **Pass booking context into WhatsAppButton on the booking page** — The booking confirmation view (`/booking/[id]`) passes a pre-filled message like `Hi AquaLudo, I have a question about my {activity} session on {date} at {time}.` Files: `app/booking/[id]/page.tsx`.
4. **Create the Resend email client and confirmation template** — Add `lib/email.ts` with a `sendBookingConfirmation(booking)` function that calls `resend.emails.send` using a single React Email template `emails/BookingConfirmation.tsx` (activity, date, time, coach name, location, booking ref, total price, customer first name). Files: `lib/email.ts`, `emails/BookingConfirmation.tsx`. Notes: `RESEND_API_KEY` and `MAIL_FROM` from `env.local`; bcc owner inbox.
5. **Trigger the email and expose contact form + footer** — (a) In the admin confirm-booking action (`app/admin/bookings/[id]/actions.ts`), call `sendBookingConfirmation` after the DB update and surface success/error via a server-action toast. (b) Add `components/ContactForm.tsx` and `app/api/contact/route.ts` that POSTs `{ name, email, message }` and emails the lead to `EMAIL_GENERAL` via Resend with a plain-text template (no DB write). (c) Build `components/SiteFooter.tsx` showing phone (tel: link), WhatsApp (deep link with generic message), and email (mailto:). Files: `app/admin/bookings/[id]/actions.ts`, `components/ContactForm.tsx`, `app/api/contact/route.ts`, `components/SiteFooter.tsx`, mounted in `app/layout.tsx`.

## Acceptance Criteria
- [ ] `https://wa.me/201011329642?text=Hi%20AquaLudo%2C%20I%20have%20a%20question%20about%20my%20Sunset%20Kayak%20session%20on%202026-08-12%20at%2016%3A00.` opens WhatsApp on mobile and web with the number and encoded message.
- [ ] The WhatsApp button is visible on `/`, `/activities`, `/booking`, `/booking/[id]`, `/contact`, and any 404 page; clicking it on `/booking/[id]` includes the booking activity, date, and time in the prefilled text.
- [ ] Marking a booking as "confirmed" in `/admin/bookings/[id]` triggers exactly one email to the customer (and a bcc to the owner) via Resend; the email contains activity, date, time, coach, location, booking ref, and price, and the action shows a success message on success or an inline error on failure without rolling back the status change.
- [ ] Submitting the contact form with valid fields POSTs to `/api/contact`, sends an email to the owner inbox with `{name, email, message}`, and the UI shows a success state; submitting with an empty message returns a 400 and an inline validation error.
- [ ] The site footer on every page shows a tappable phone number, a WhatsApp link (generic greeting), and a mailto link; each opens the correct handler on mobile and the correct app/tab on desktop.
