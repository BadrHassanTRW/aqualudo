# Task 10. Platform Infrastructure

## Goal
Stand up the minimum hosting stack for the AquaLudo MVP: a Vercel project for the Next.js app, a Supabase Postgres database, the `aqualudo.net` custom domain on HTTPS, environment-based secrets, a separate staging environment, daily DB backups, and versioned SQL migrations. Everything must be operable by the owner without DevOps help.

## Steps
1. **Create Vercel project and Supabase project** — In Vercel, import the Git repo and create a single project named `aqualudo` (framework preset: Next.js); in Supabase, create a new project in the closest region (e.g. `eu-central-1`), save the database password to a password manager, and copy the `Project URL`, `anon` key, and `service_role` key. Files: `infra/vercel-project.md` (notes only). Notes: production-only at this point; staging is wired in step 3.
2. **Add `.env.example` and wire environment variables on Vercel** — Create `.env.example` at the repo root listing every required key (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, plus any future payment/API keys) with empty values; in Vercel Project Settings → Environment Variables, add the same keys for the **Production** environment only, marked sensitive. Files: `.env.example`, `.gitignore` (ensure `.env.local` is ignored). Notes: never commit real values; document each key in `.env.example` with a one-line comment.
3. **Provision a separate staging environment** — In Supabase, create a second project (`aqualudo-staging`) with its own credentials; in Vercel, add a second environment named **Preview** (or a new branch-based environment) and point it at the staging Supabase keys. Files: `infra/staging.md` (URLs, DB names, how to promote a change). Notes: do not share keys between staging and production; staging database can be reset freely.
4. **Connect the `aqualudo.net` custom domain on Vercel with HTTPS** — In the domain registrar, point the apex `aqualudo.net` (A/ALIAS) and `www.aqualudo.net` (CNAME) to Vercel; in Vercel Project Settings → Domains, add both, verify ownership, and let Vercel provision the Let's Encrypt certificate. Files: `infra/dns.md` (registrar, records, TTL). Notes: enforce HTTPS by enabling the "Redirect to HTTPS" toggle; confirm the cert is `Active` before declaring done.
5. **Enable Supabase daily backups and document restore** — On the production Supabase project, confirm the project's plan supports automated daily backups (Pro plan or the equivalent on the chosen tier) and note the retention window in `infra/backups.md`; on staging, enable backups as well but with a shorter retention. Files: `infra/backups.md` (schedule, retention, who has the dashboard login, how to request a restore). Notes: out of scope per MVP — no PITR, no off-site copy, no restore drill, but the schedule itself must be live.
6. **Adopt versioned SQL migrations as the single source of truth** — Add the Supabase CLI to the repo (`supabase init`), put every schema change as a timestamped file under `supabase/migrations/`; document the three commands (`supabase db pull` from prod, `supabase db push` to staging, `supabase db push --linked` to prod) in `infra/migrations.md`. Files: `supabase/config.toml`, `supabase/migrations/0001_init.sql` (initial baseline), `infra/migrations.md`. Notes: apply the baseline to both databases before any app code assumes the tables exist; do not edit the DB by hand.
7. **Smoke-test end-to-end before signing off** — Run a production deploy, open `https://aqualudo.net` in a private browser, confirm the site loads over HTTPS, the homepage renders, and the Supabase connection works (e.g. a read of an existing table); open the staging URL and confirm it talks to the staging DB. Files: `infra/runbook.md` (deploy, rollback, who to call). Notes: this step is the gate for marking Task 10 complete.

## Acceptance Criteria
- [ ] Vercel project `aqualudo` exists, linked to the Git repo, and a production deploy succeeds.
- [ ] Supabase production project exists, is reachable from Vercel, and a test query from the app returns a row.
- [ ] `https://aqualudo.net` (and `www.`) loads the site, shows a valid Let's Encrypt certificate, and HTTP requests redirect to HTTPS.
- [ ] `.env.example` is committed at the repo root, lists every required key, and no real secret is present in the repo or in `git log`.
- [ ] A separate Supabase staging project and a separate Vercel environment exist; the staging URL does not touch the production database.
- [ ] Supabase daily automated backups are enabled on production with a documented retention window, and the schedule is visible in `infra/backups.md`.
- [ ] `supabase/migrations/` contains timestamped `.sql` files, the baseline has been applied to both prod and staging, and a fresh local `supabase db reset` reproduces the schema from those files.
